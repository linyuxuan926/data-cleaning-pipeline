# V3 评审草案：产品交互与分阶段交付

> 状态：供评审的拟议方案，尚未实现。日期：2026-11-06。本文只记录 V3 的产品行为、接口依赖与验收条件，不宣称现有服务已具备这些能力，也不把现有 V1/V2 的构建、浏览器验收或 Python 测试结果（包括已有的 152 项 pytest）作为 V3 验证证据。

## 1. 目标、范围与已有基础

目标仍为：上传结构化文件 → 配置解析和字段 → 预览 → 编排并保存规则 → 创建异步任务 → 跟踪真实执行 → 查看报告与结果 → 下载产物。Java 是浏览器唯一业务入口，Python 承担读取与清洗，MinIO 保存文件和产物，MySQL 保存业务状态，RabbitMQ 解耦提交与执行。

V3 首版保持单机部署。CSV 与 Parquet 采用有界流式读写；需要全局统计、去重或多遍处理的规则使用每次尝试独立的 SQLite scratch 临时文件。SQLite 只作为 Worker 本地计算暂存，不作为新的业务数据库，不替代 MySQL，不作为浏览器查询服务，也不引入跨节点协调承诺。采用流式处理不代表自动放宽现有文件、行列、单元格和磁盘限制；提高容量必须经过独立资源验证。

| 范围 | 当前已有 | V3 拟议、尚未实现 |
| --- | --- | --- |
| 文件与解析 | 独立 fileId / uploadId、分片、完整 SHA-256、上传与解析状态分离、CSV 解析选项、XLSX 工作表、稳定字段 ID、样例推断与类型覆盖 | 可查询和恢复的上传会话、上传并发配置、暂停与继续、文件列表分页 |
| 规则 | 19 类规则表单、稳定字段引用、不可变规则集版本、历史版本加载、另存为、规则与输入快照 | 完整元数据、条目启用、独立复制、归档删除、版本比较、版本化 JSON Schema、严格配置顺序 |
| 执行 | 异步 Worker、队列、outbox、租约、取消请求、手动重试和自动恢复 | 独立 attemptId 历史、CANCELING / CANCELED、真实阶段与行数进度、7 天任务幂等、流式与磁盘暂存执行 |

当前规则会按阶段重排；当前取消立即写为 CANCELLED；当前重试主要覆写任务的当前尝试信息。V3 的配置顺序、取消确认、独立历史均属于明确的行为变化，不能只修改文案后视为完成。

## 2. 页面结构与核心交互

### 2.1 文件列表与解析详情

文件列表显示文件名、格式、大小、上传者、创建时间、上传状态、解析状态和可用操作。名称、格式、解析状态、创建时间采用服务端筛选与游标分页。上传成功与解析成功分别显示，解析失败保留原始对象，允许调整选项后重新解析；不允许以“上传成功”替代内容有效性判断。

解析详情保留编码、分隔符、工作表、缺失标记、字段推断、手动类型覆盖和有限样例。字段使用稳定 ID，展示原始名称及当前类型。修改选项后明确标记“尚未应用”，要求重新解析成功再创建任务。预览只覆盖样例，界面必须说明完整执行仍会验证全部文件及容量。

新任务固定文件对象引用、文件摘要、解析参数、字段映射与配置版本。已有任务及其重试不采用后续重解析结果。文件信息中的内部对象引用放在详情中，下载仍通过受保护的 Java 接口提供。

### 2.2 上传会话

上传会话成为独立列表，显示会话状态、文件名、创建与到期时间、已确认字节数、已完成分片数 / 总分片数和最近错误。支持筛选与分页；上传期间可以离开工作台、查看任务或再次进入会话列表。

上传会话只使用一套 `state` 枚举：`UPLOADING`（可接收分片）、`PAUSED`（暂停）、`COMPLETING`（合并与校验）、`COMPLETED`（原始文件持久化完成）、`FAILED`（本次会话失败）、`ABORTED`（主动放弃）、`EXPIRED`（会话过期）。创建成功即为 UPLOADING；初始化请求尚未成功只是前端请求状态，不再额外保存 INITIALIZING。普通分片网络失败记录 lastError 并允许重试，不自动把可恢复会话置为 FAILED。阶段 0 将该枚举及合法转换同步到 schema、OpenAPI、Java 和 TypeScript。

上传、文件解析和任务执行是三类独立状态：upload session 的 COMPLETED 仅表示原始内容已保存；`file.status=READY` 表示 raw 对象可用；`file.parseStatus` 独立为 `UNPARSED`、`PARSED`、`FAILED`。合法组合包括 `session.state=COMPLETED + file.status=READY + file.parseStatus=FAILED`，此时保留原件并提供重解析入口。只有 READY 且 PARSED 的文件才能创建任务。任务 / attempt 使用 QUEUED、RUNNING、CANCELING、SUCCEEDED、FAILED、CANCELED，不能用任务 SUCCEEDED 表示上传或解析成功，也不能因解析失败把已完成的上传会话改成 FAILED。文件归档或删除同样不回写历史任务状态。

核心行为：

1. 选择文件后计算完整 SHA-256 并创建独立会话；界面区分“计算摘要”“上传分片”“合并与校验”“解析”。首版仍受已评审文件体积上限约束。
2. 分片进度按服务端确认的唯一分片字节数累计。重传同一分片不能重复增加已传字节；浏览器瞬时发送字节与服务端确认进度不得混用。
3. 设置上传并发数。该值指单个会话同时发送的分片数量，与用户活跃清洗任务上限分别命名；默认值、最大值和每用户总在途请求上限由服务端策略返回，前端选择不得越过其限制。
4. 暂停停止调度新分片；已在途请求可能仍完成，随后重新查询服务器会话状态。暂停不等于删除已传分片。
5. 刷新或重进后可查看会话进度。恢复传输时要求用户重新选择本地文件，校验大小与完整摘要后仅补传缺失分片；不能假定刷新后浏览器仍能读取原 File。
6. 可重试网络失败，采用有上限的退避；认证失效、摘要不符和会话过期须有明确处理。放弃会话需确认，并由服务端清理临时数据。
7. 完成接口幂等，缺片、分片长度错误或摘要不符不得把文件标记为可用。解析失败与上传校验失败给出不同状态和下一步入口。

服务端查询应返回已收到分片、会话限制、到期时间和可恢复状态。分片列表同样分页；前端不能依靠本地缓存宣称某个分片已经持久化。

### 2.3 规则库与版本

规则库展示名称、描述、创建者、创建时间、更新时间、启用状态、适用字段和当前版本。支持名称、启用状态、时间筛选和服务端分页。创建者与审计时间由服务端生成，前端只读。

需要分别保存两层启用状态，不能用同一个字段覆盖：

- `ruleSet.enabled`：整个规则集当前是否允许被新任务引用；属于规则集元数据，停用后新任务不能使用该集的任何版本。服务端保留修改者、修改时间及状态变更审计。
- `ruleVersion.rules[i].enabled`：该不可变版本中单条规则的必填 boolean，与条目 `id`、`type`、参数一起保存进版本 JSON、复制结果和任务快照。禁用条目仍留在数组与配置摘要中，报告状态为 DISABLED，执行时跳过；不能仅在前端隐藏、过滤后保存，或因 schema 未声明该字段而丢失。

修改条目 enabled 产生新版本；规则集 enabled 的当前接纳状态与版本内条目开关分别展示。任务快照记录创建时的规则集元数据与完整版本，后续任一层启停均不改变已有任务及重试。

规则集支持创建、读取、修改、复制和删除。修改产生不可变新版本；复制生成新 ID 与 v1，复制名称、描述、字段与参数，同时重新记录创建者。复制界面标明来源版本。删除采用归档语义，禁止新引用，保留历史任务访问其版本快照的能力，不进行级联物理删除。

版本详情显示版本号、参数契约版本、更新时间、修改者和规则内容。可选择两个版本比较描述、启用状态、字段、参数和顺序变化。从旧版本编辑应明确提示“将基于 vN 创建新版本”，不能覆盖旧版本。加载其他规则或离开编辑器前，对未保存修改提供保存、放弃、继续编辑三个选择。

### 2.4 规则编辑器与严格配置顺序

每条规则显示配置序号、名称、说明、启用开关、字段、参数和失败策略，支持复制、删除、上移、下移；可补拖动排序，但必须保留键盘可用的排序按钮。复制条目生成新的条目 ID；条目 ID 与字段 ID、规则集 ID 不混用。

新任务严格按启用条目的配置数组顺序执行，不自动按类型或阶段重排。阶段标签仅用于解释作用，不改变执行顺序。编辑器序号、提交快照、Worker 顺序、日志、报告的规则定位必须一致；禁用条目明确显示“跳过”，不能悄悄从保存内容中消失。

字段选择器按当前步骤之前的有效字段映射更新。稳定字段 ID 不因重命名改变；已被前序规则删除的字段不能在后续规则中继续使用。保存或提交前应定位缺失字段、无效参数和非法顺序，并给出对应条目的错误。规则集未通过完整验证可留在本地编辑草稿，但不能作为可执行版本发布。

失败语义固定为：

- `drop`：当前规则确认违规后立即移除该记录；不再进入任何后续规则或统计。
- `mark`：保留记录、累计该次违规，继续接受后续规则；同一行的多个违规全部保留。
- `fail`：该尝试失败，错误中定位规则、字段和原因，不发布成功结果。
- `null`：适用于允许该策略的类型转换和异常规则，将对应字段置空并记录违规；后续规则看到修改后的空值。

“立即移除”指在当前规则边界生效。不得保留 V2 隐式 validation 阶段，将多个不相邻规则先统一评估后再删除。前序 mark 行仍可能被后续 drop 移除；报告区分曾被标记的事件与最终保留的标记行。

规则参数由服务端版本化 JSON Schema 约束，保存并固定 schemaVersion。前端可以保留专用表单，但其必填项、类型、边界和允许值必须与指定 schema 一致；Java 和 Python 校验同一版本的配置。未知或不再支持的 schema 版本只读显示，并提供显式迁移流程；不静默丢弃未知字段，不允许 arbitrary code / eval / SQL。

旧任务重试必须保留原执行模式及原始规则语义。迁移已有规则时，展示旧实际顺序与新配置顺序的差异，用户保存新版本后才用于新任务。新任务不能在未提示的情况下继承旧 phase 重排。

### 2.5 任务列表与创建

任务列表提供状态、创建时间区间、文件名筛选；管理员列表额外支持所属用户。所有条件传给服务端，筛选改变后回到第一页，刷新保留筛选条件。游标与筛选绑定，不允许用旧游标拼接新条件。列表统计如果只代表当前页，应直接标注；跨页统计使用独立服务端聚合，不把当前页行数称为全部任务数。

创建前显示输入文件、解析版本、规则版本、启用规则数、实际配置顺序、输出格式和处理限额。解析未成功、规则验证失败、限额读取失败、解析修改未应用时不能提交。点击后固定本次提交内容，防止保存规则期间用户继续修改输入造成快照不一致。

任务幂等保留期为 7 天：客户端一次明确提交生成一个 Idempotency-Key，网络重试和超时确认复用该键；用户明确“再次运行”才生成新键。后端按用户、操作与规范化请求摘要绑定幂等键，首次创建返回 201，重复同一请求返回 200 及原任务，复用键但内容不同返回 409。幂等记录与任务创建、初始 attempt、outbox 在同一事务中提交。权限始终重新校验，幂等不能绕过已禁用用户或资源归属。

前端不将请求超时展示为“任务一定未创建”，而显示“正在确认提交结果”，通过查询或带同一键重试找回原任务。客户端提示保留期；超过 7 天的旧请求不可承诺仍被去重。重试尝试也应使用独立的操作幂等键，避免重复生成 attempt。

### 2.6 任务详情、独立尝试历史与取消

任务详情包括当前执行、执行历史、日志、快照、报告、结果预览和下载。任务保持稳定 taskId，每次手动重试、自动恢复产生独立 attemptId，并保留尝试序号、触发原因、开始结束时间、状态、错误、报告和产物引用。

执行历史采用服务端分页。选择历史尝试后，日志、报告、预览与下载全部切换到所选 attemptId；当前任务状态仍以当前尝试为准，不因查看历史而回退。日志按尝试和游标加载，保留现有去重及有界渲染机制，切换任务或尝试时隔离旧请求。

拟议任务状态统一为 `QUEUED`、`RUNNING`、`CANCELING`、`SUCCEEDED`、`FAILED`、`CANCELED`。V3 输出统一采用 CANCELED 拼写；旧 CANCELLED 仅由兼容层读取与映射，不能让前端同时推断两个不同终态。

取消行为：

- 排队任务在服务端确认尚未领取后可直接进入 CANCELED，随后到达的旧消息不能执行。
- 执行中任务先进入 CANCELING，界面显示“正在取消，等待执行进程停止”，继续轮询并禁止重复取消或提前重试。
- 监督进程确认执行子进程停止后才能写入 CANCELED；只有 lease fencing 而未确认停止时显示 FAILED/CANCEL_UNCONFIRMED，不能把它当作已停止。取消与成功竞争须由服务端状态机裁决，界面只呈现已确认结果。
- 普通用户仅能控制自己的任务。管理员可以只读查看全部任务、日志、报告和产物；取消与重试仍由所属用户操作，除非未来另有明确授权设计。

### 2.7 真实执行进度

显示排队、下载、读取、规则执行、全局统计 / 暂存、导出、上传产物、提交报告等真实阶段，以及当前规则、已处理行数、开始时间、耗时和最近心跳。多遍算法必须说明当前遍次或当前阶段，不能把各遍行数相加称为已读输入行数。

进度事件至少需要 stage、stageLabel 或本地化键、ruleId / ruleIndex、processedRows、totalRows（未知为 null）、startedAt、updatedAt、heartbeatAt 和 attemptId；可选 passIndex / passCount。processedRows 必须说明是当前阶段处理数还是唯一输入记录数。耗时使用服务端开始时间推导，最终耗时以服务端确认值为准。

只有已知且可信的阶段分母才显示该阶段确定比例。总行数或整体工作量未知时使用不确定进度、行数和耗时，不把固定的 5 / 10 / 80 / 90 / 98 阶段权重展示成精确总体完成百分比，也不根据时间线性增长。心跳停滞显示“状态更新延迟”，不能由前端自行判定失败或擅自发起重试。

### 2.8 报告与成功结果预览

报告属于 attempt。基础指标和语义如下，所有计数须由真实执行数据生成：

| 指标 | V3 定义与界面名称 |
| --- | --- |
| inputRows | 输入行数 |
| outputRows | 输出行数，包含最终保留的标记行，不能称为“全部质量合格行数” |
| removedRows | 最终移除的唯一行数；满足 inputRows = outputRows + removedRows |
| flaggedRows | 最终输出中仍带质量问题的唯一行数；前序被标记但后续移除的行不计入 |
| validOutputRows | 输出中未带质量问题的行数；按既定质量标记口径，满足 outputRows = validOutputRows + flaggedRows；只表示已配置规则下未标记，不宣称数据绝对正确 |
| dirtyRows | 有至少一条违规的唯一原始记录数，可与 removedRows 不同 |
| issueCount | 违规事件条数，同一记录可贡献多条 |
| changedCells | 实际变更单元格数，需明确单元格跨多条规则多次修改的计数口径 |

新增按规则、字段、错误码和处理动作的聚合，分别标明“事件数”还是“去重记录数”。多个分组的记录数可能重复，不能简单相加代替唯一违规行数。输出保留率与有效输出率分开展示，并明确分母。统计填充和 IQR 保留样本数、无效数、阈值、回退策略等说明；失败报告提供已完成的诊断与失败位置，不展示为成功结果。

成功尝试增加“结果预览”，使用真实导出产物或导出时同步生成的预览对象，显示最终字段顺序、最终名称、类型与质量标记，可展开完整错误。不得重新运行清洗来生成预览，不得用原始输入替代，也不得由浏览器下载整个大文件后再截取样例。

首版建议生成有界预览对象，以预览可用行数和字节上限控制成本，并在其范围内提供游标分页。界面分别显示“全部输出 N 行”和“可预览前 M 行”，明确截断与下载入口；不把有限样例的分页冒充整份结果分页。预览上限由评审后的策略返回，不在前端硬编码。违规明细预览同样标明覆盖范围，并提供完整脏数据下载。

### 2.9 管理页面

保留用户列表、启停、角色与最后一位有效管理员保护；列表改用服务端分页。账户停用后会话立即失效，管理员修改自身角色后界面及时同步权限。

全部任务支持与个人任务一致的筛选、分页、真实进度和 attempt 历史，额外展示所属用户。管理员对其他用户任务仅有既定只读能力；文件与规则不因角色自动开放所有写权限。

处理策略页面展示当前生效版本、修改时间、修改者、默认值与安全上限，补充上传并发、会话期限、流式批大小、scratch 磁盘预算和预览预算中经评审允许配置的项目。用户界面只展示影响操作的实际限额；SQLite、批大小等实现信息留在管理或运维视图。修改只影响新快照，已有任务重试沿用原策略，同时继续接受当前账户权限、提交频率与资源接纳检查。

## 3. 拟议 V3 接口约束

V3 任务和相关新接口使用 `/api/v3`，与现有接口显式隔离；本文列举的是拟议接口，不代表已可调用。所有列表采用不透明 cursor，`pageSize` 默认 20、最大 100。响应统一为 `{items, nextCursor, hasMore}`；需要总量的视图另行取得真实聚合。游标需绑定排序、筛选和用户范围，非法或不匹配游标返回明确错误。

| 能力 | 拟议接口与关键约束 |
| --- | --- |
| 文件列表 | `GET /api/v3/files?cursor=&pageSize=20&name=&format=&parseStatus=&createdFrom=&createdTo=` |
| 上传会话 | `POST /api/v3/uploads`；`GET /api/v3/uploads`；`GET /api/v3/uploads/{uploadId}`；`GET .../{uploadId}/chunks?cursor=&pageSize=20`；`PUT .../{uploadId}/chunks/{index}`；`POST .../{uploadId}/complete`、`/pause`、`/resume`；`DELETE .../{uploadId}`放弃，均以会话为作用域 |
| 规则库 | `/api/v3/rule-sets` 的列表、创建、修改、归档；`POST .../{id}/copy`；`GET .../{id}/versions?cursor=&pageSize=20`；版本内容含 schemaVersion 与不可变顺序 |
| 参数契约 | `GET /api/v3/rule-schemas/{schemaVersion}` 和 `POST /api/v3/rules/validate`，指定类型的只读 schema；响应不能含可执行脚本 |
| 任务创建 | `POST /api/v3/tasks`，携带 Idempotency-Key；固定输入、规则和策略快照，首次201，7天内重复相同请求200并返回原任务 |
| 任务列表 | `GET /api/v3/tasks?cursor=&pageSize=20&status=&createdFrom=&createdTo=&fileName=`；管理员 `/api/v3/admin/tasks` 增加 ownerId |
| 任务与尝试 | `GET /api/v3/tasks/{taskId}`；`GET .../{taskId}/attempts?cursor=&pageSize=20`；`GET /api/v3/tasks/{taskId}/attempts/{attemptId}`；当前 attempt 与历史 attempt 明确区分 |
| 日志与报告 | `GET /api/v3/tasks/{taskId}/attempts/{attemptId}/logs?cursor=&pageSize=20`；`GET .../{attemptId}/report`；日志 cursor 不跨 attempt 复用 |
| 产物与预览 | `GET /api/v3/tasks/{taskId}/attempts/{attemptId}/artifacts/{kind}`；`GET .../{attemptId}/preview?cursor=&pageSize=20`；有界违规预览同样分页并返回覆盖范围 |
| 取消与重试 | `POST /api/v3/tasks/{taskId}/cancel`；`POST .../{taskId}/retry` 返回新 attemptId；请求幂等且执行控制权限独立校验 |
| 管理与策略 | `/api/v3/admin/users` 的分页和修改、`/api/v3/system/settings` 读取、`/api/v3/admin/system/settings` 版本化更新 |

任务创建请求的最终字段、筛选边界、统一错误码、上述上传会话状态转换、稳定排序键与游标格式在阶段 0 契约中锁定。时间接口使用带时区的时间戳；页面按用户时区显示，时间区间建议采用左闭右开语义并在选择器说明。

## 4. 阶段 0 冻结、阶段 1 落地的基础设计

### 4.1 安全、权限与 schema

Java 对每次操作验证登录、用户启用状态、角色、资源归属。attemptId、uploadId、cursor、产物路径和幂等键都不能扩大权限范围。普通用户只能读取自己的资源；管理员保留已约定的任务只读访问。服务端不能信任前端隐藏按钮或字段 ID。禁止用户提交可执行 Python、SQL、shell 或 eval 表达式。

规则 schema、规则版本、执行语义版本、输入快照和策略快照共同冻结。JSON Schema 校验之外仍保留跨字段、字段生命周期、正则资源和业务约束校验。未知版本、未知字段和非法失败策略必须明确失败，不静默接受。

### 4.2 attempt、outbox 与取消状态机

任务创建、独立 attempt、快照、7 天幂等记录与 outbox 以 MySQL 事务提交；outbox 不是仅在内存中记一次待发消息。RabbitMQ 投递、重复消息和租约恢复必须绑定 taskId / attemptId、租约身份与事件序列，过期尝试不得覆盖当前尝试或别人的产物。

手动重试与自动恢复保留旧尝试终态，生成新尝试，产物目录按 attemptId 隔离。日志可定位尝试和规则。CANCELING 的完成、超时与失联恢复路径需要明确，不得把“已请求取消”直接当作“已停止”。终态只能按已评审状态机写入。

### 4.3 资源与临时数据边界

流式执行采用有界批次；全局去重、统计与多遍数据使用每 attempt 独立 SQLite scratch。必须预算数据库、WAL、临时排序和中间文件的总磁盘使用，限制任务与平台占用；超限明确失败，不伪装为规则违规。SQL 仅为服务端固定计算逻辑，不接收用户 SQL。

暂存文件随成功、失败、取消和启动恢复执行清理策略。不能因为 API 回应快或预览有效就声称整份文件已验证。Worker 只通过受保护的 Java 协议写业务状态，不直写 MySQL。

## 5. 里程碑与验收门槛

阶段编号、范围与 [SYSTEM-DESIGN.md 第 10 节](SYSTEM-DESIGN.md#10-开发里程碑和验收门槛) 一致：0 契约冻结、1 安全纵向主链、2 可靠性与历史、3 容量与部署。完整页面主流程在阶段 1 交付，不推迟到阶段 3。以下均为未来计划，当前已有测试只用于回归基线；每个 V3 条款须提供新证据，不能用旧测试数量替代。

### 阶段 0：契约冻结

交付：本产品方案、主架构方案、规则执行规格、版本化 JSON Schema、正式 OpenAPI 草案、报告样例、V2/V3 engineVersion 分界、上传 / 文件解析 / 任务状态和权限矩阵。明确规则集与条目的 enabled 分别存储，并锁定严格顺序、drop / mark、字段生命周期、validOutputRows、7 天幂等、attempt / event / outbox、cursor 以及旧数据迁移设计。

依赖：产品、Java、Python、前端和测试共同确认命名与语义。契约样例是设计样例，不是运行结果；此阶段不声称 V3 已有可部署主链。

验收：

1. schema 与 Java / Python / TypeScript 类型一致性检查通过，报告和规则样例按指定 schema 校验，条目 enabled 往返不丢失。
2. MySQL 模型与索引、权限矩阵、attempt 和取消状态转换、幂等事务边界、上传状态转换完成评审。
3. 配置顺序、禁用规则跳过、单 L CANCELED、7 天保留、分页默认 20 / 最大 100、旧历史不可重建等兼容边界明确记录。

### 阶段 1：安全纵向主链与完整 UI 流程

交付：V3 Flyway 和兼容读、可恢复上传会话及摘要 / 解析、USER / ADMIN 权限、规则元数据与不可变版本 / 字段绑定 / schema、7 天幂等、首个独立 attempt 与事务 outbox、严格配置顺序执行。浏览器必须完整走通文件上传与恢复、解析修正、规则创建 / 启停 / 复制 / 保存、任务提交、真实异步执行、日志、报告、结果预览和授权下载，并包含管理员基本页面。CSV、XLSX、Parquet 均输出真实结果、issue 与 report。

依赖：阶段 0 契约已冻结；Java / 数据库先落地 schema / state / attempt / context，Python 对接固定上下文和报告，前端接真实 API。独立 attempt、事件身份、权限及 outbox 安全边界从首条可运行链路就启用，不能留到后续补接。此阶段先证明正确主链，阶段 2 再完成历史恢复和异常竞争全面验证；阶段 3 才发布实测容量结论。

验收：

1. 全新空库及 V2 升级环境均可运行；三格式浏览器端到端真实完成，结果预览与下载属于同一 attempt；没有模拟接口填补主链。
2. USER / ADMIN、跨用户 upload / attempt / 产物访问、已禁用会话、最后有效管理员和公式注入防护均通过验证。
3. 并发重复 POST 只生成一个 task / 首个 attempt / outbox；内容不同复用键被拒绝；三位用户争抢额度不会超额。
4. 每类规则逐行核验原始值和报告，交换规则顺序改变预期行为；drop 即时离开后续集合，mark 持续累计，禁用项保存并跳过，旧 V2 重试保留旧模式。
5. 报告验证 inputRows = outputRows + removedRows、outputRows = validOutputRows + flaggedRows；页面不把包含标记行的输出称为全部质量合格。未知分母不虚构总体百分比。

### 阶段 2：可靠性与不可变历史

交付：完整 attempt / event ledger、eventId / eventSeq 幂等与 fencing、CANCELING 确认、人工和有限自动新 attempt、独立历史查询、所有列表完整服务端分页与筛选、结构化进度、attempt 级日志 / 报告 / 预览 / 产物、问题审计、object catalog / tombstone / cleanup worker。强化会话恢复、并发分片和过期边界；已有上传 / 任务 UI 同步呈现真实落库状态。

依赖：阶段 1 的安全主链可部署且已验收。Java attempt / event 事务与 Python Worker 监督、取消、旧租约隔离必须联测，UI 不从本地请求结果推断终态。

验收：

1. 重复消息与回调、同 eventId 不同内容、乱序 seq、旧 attempt 成功竞争、取消 / 完成竞争均不能回退状态或覆盖别的尝试。
2. 槽位竞争、死 Worker、新恢复 attempt、RabbitMQ 重启、对象已写但数据库失败均有真实故障验证；旧 attempt 日志、报告、错误和产物仍可审计。
3. 刷新 / 断网后上传恢复、重复与并发分片、暂停 / 继续、摘要不符、会话过期，以及软删除 / 有效引用 / 租约保护下的清理均通过测试。
4. 文件、规则、用户、任务、attempt 和日志等列表按默认 20 / 最大 100 分页；跨页插入、筛选改变、同时间排序、cursor 权限范围与历史尝试切换不混淆数据。
5. CANCELING 等待实际停止；无法确认时以FAILED/CANCEL_UNCONFIRMED结束并fencing，不能称为已停止；totalRows 未知时用阶段、处理行数、耗时和心跳解释进度，未确认的结果不作为成功产物开放。

### 阶段 3：容量、安全与部署验证

交付：在前两阶段可部署实现上测量 CPU / RAM / disk 配额，完成 CSV / Parquet 有界批次与 SQLite scratch 全局步骤的容量验证、XLSX 有界策略、安全压力、HTTPS 代理、备份 / 恢复、OpenAPI 发布、健康检查与告警、保留清理、迁移 / 回退和单机运维指南。容量优化不得改变已经验收的规则、报告、权限和顺序语义。

依赖：阶段 1 完整 UI 主链和阶段 2 可靠性 / 历史通过验收。跨批次全局 first / last 去重、统计填充、阈值与来源行序须与对照实现一致；SQLite 仍只是 per-attempt scratch，不成为业务数据库。

验收：

1. 记录硬件、容器配额、依赖 hash、数据摘要、文件字节 / 行列、规则、并发、内存 RSS、scratch 峰值、耗时、取消点和产物 hash；未跑的数据标为待验证，不提前承诺容量。
2. SQLite 数据库、索引、WAL、排序、中间文件与输出共同计入磁盘预算；超限、Worker 中断和启动清理不泄漏临时数据或绕过额度。
3. CSV / Parquet 全局语义跨批一致，XLSX 解压限制、regex、SSRF、路径、zip bomb 和敏感日志保护均提供证据。
4. 从空卷重建 Compose，演练备份 / 恢复与迁移；HTTPS、内部接口隔离、依赖漏洞、对象保留和清理告警完成验证。
5. 桌面 / 窄屏、键盘操作、长列表有界渲染、上传恢复及结果预览再次验收；发布说明分别列出 V3 新验证与 V1/V2 回归，不用现有 152 项 pytest 代替 V3 测试。
